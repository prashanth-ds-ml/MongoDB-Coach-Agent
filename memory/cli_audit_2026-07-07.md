# CLI Behavior Audit (2026-07-07, session 9)

Last updated: 2026-07-07

Related: [[Memory Home]], [[session_handoff|Session Handoff]], [[decision_log|Decision Log]], [[coach_flow_spec|Coach Flow Spec]]

## Scope

A deep audit of `src/certcoach/cli.py` (3445 lines) -- every menu, option, and interaction --
run via three parallel read-only passes (navigation/chrome, study/practice/mock loops,
reports/imports). Goal: find real bugs, dead ends, and inconsistencies, not style nits. All
line numbers below are as of this commit; re-verify before trusting them in a future session
if the file has moved on.

## Confirmed Bugs (real user impact)

1. **Onboarding "No" doesn't roll back the plan it just rejected** (`cli.py:399-422`) --
   `exam_date`/`study_calendar` are saved *before* the final confirmation. Answering "no" tells
   the user to restart, but restarting now finds both fields populated and skips onboarding
   entirely into the rejected plan.
2. **Ctrl+C crashes almost everywhere** -- ~40+ raw `Prompt.ask`/`Confirm.ask` calls have no
   `(KeyboardInterrupt, EOFError)` guard, and the top-level handler only catches `Exception`
   (~line 3438), which doesn't include `KeyboardInterrupt` (a `BaseException`). Ctrl+C at most
   prompts throws a raw traceback instead of the documented "session saved" exit.
3. **Mock-resume can crash or silently corrupt scoring** (`cli.py:1226-1233`) -- saved
   `user_answers`/`flagged` are restored unconditionally; `questions` is only restored if its
   length still matches. Mock question sets are re-drawn randomly each run, so a stale saved
   session can have mismatched lengths -> `IndexError` crash, or answers/flags silently mapped
   to the wrong questions.
4. **Mock shortfall report is rendered then wiped before it's readable** --
   `_render_shortfall_report()` (`cli.py:2297-2332`) prints correctly, but both callers
   (`run_full_mock`, `run_timed_mock`) immediately call into `run_practice_questions`/
   `run_exam_simulator`, which `clear()` the screen before the user can read anything. The
   documented "never silent padding, explicit report" guarantee is functionally silent.
5. **Wrong "blocked" message for non-3E/2M practice calls** -- the shortfall gate in
   `run_practice_questions` (~line 1564) fires the "3 Easy + 2 Medium... Concept Practice
   Blocked" message for any caller short on questions, including the Diagnostic Test, Mini-Mock,
   Pop Quiz, and Boss Fight -- none of which use a 3E/2M mix. These hard-abort instead of
   gracefully running fewer questions (unlike Full/Timed Mock, which do handle shortfall
   gracefully via `preselected_questions`).
6. **Boss Fight mislabels "no questions available" as a loss** (`cli.py:3336`) -- a `None`
   score (nothing to practice) prints "Boss Defeated You!", indistinguishable from an actual
   scored loss.
7. **`num` is cosmetic in `run_practice_questions`'s non-mock branch** (~line 1535) -- slicing
   is hardcoded to 3 Easy + 2 Medium regardless of the caller's `num`. The Error Book "Targeted
   Recovery Practice" call (`cli.py:2520`, `num=3`) expects a short drill; the shortfall gate
   also checks the wrong target (`num=3` instead of the real 5-question composition).

## Menu/Navigation Inconsistencies

8. **Dead "back" alias** in `run_settings_submenu` -- `"b"` is bound to Recalibrate earlier in
   the same `elif` chain, permanently shadowing the later `"b"` = back-to-menu branch (~2984 vs
   ~3004).
9. **`ask()` doesn't add "back"/"b"/"menu" to Rich's `choices` list** in several menus
   (`run_question_bank_reports`, `run_account_submenu`, `run_model_manager`) -- typing "back"
   gets rejected and re-prompted forever instead of working.
10. **"q" means different things in different menus** -- full program quit in Settings,
    one-level-back in Library.
11. **`run_account_submenu`'s prompt excludes "q"** from its choices list entirely.
12. **Scenario Simulator ignores "back"** (only honors "q"/Ctrl+C) -- typed "back" gets
    submitted to the LLM as a scenario answer instead of navigating away.

## Smaller Correctness/UX Gaps

13. Same-day exam date incorrectly passes the "must be in the future" check (00:00 vs 23:59
    comparison bug in `run_onboarding`).
14. Typing "back" at the onboarding experience-level prompt silently becomes "Beginner" with no
    notice to the user.
15. UTC-vs-local date comparison can be off by a day at timezone boundaries.
16. Timer isn't shown/enforced while browsing the Summary Grid -- abrupt, unexplained
    auto-submit when time runs out mid-browse.
17. Timed Mock's printed pacing target ("~28m") doesn't match the actual enforced cutoff (30m,
    `num * 90s`).
18. "Model Manager" menu framing implies model-switching but there's no setter anywhere -- it
    can only inspect/preload/unload, not switch the configured model.
19. 70%-mastery lock message is hardcoded in 4 places instead of reading
    `status["unlock_threshold_percent"]`.

## Fix Status

**All 19 findings fixed (2026-07-07, session 10)**, plus one additional issue found during the
fix pass itself: the installed `certcoach` console-script entry point called `main_menu()`
directly, bypassing the `if __name__ == "__main__":` graceful-exit wrapper entirely (that block
only ever ran for `python cli.py`, never for real users) -- combined with `run_onboarding()` and
the daily-agenda block not being wrapped in `try/except SystemExit`, typing "q" while studying
today's agenda skipped the "Session saved" message and let `SystemExit` propagate raw out of the
process. Fixed by wrapping `main_menu()`'s entire body in one `try/except (SystemExit,
KeyboardInterrupt, EOFError)/except Exception/finally: exit_message()`, replacing the previous
ad hoc per-branch handling. See `memory/decision_log.md` (2026-07-07, session 10) for the full
list of what changed and why. 311/311 unit tests pass (2 pre-existing tests needed fixture
updates since they were unknowingly relying on the old, looser shortfall gate -- see the
decision log entry).
